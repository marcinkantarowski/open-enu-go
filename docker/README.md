# docker

- `compose.dev.yml` - the dev stack: postgres, redis, mercure, `api`, `worker`, `scheduler`,
  the three Nuxt dev servers, mailpit; `webhook-echo` and `e2e` behind the `e2e` profile.
  Scripts read it through `scripts/lib/compose.sh` (`COMPOSE_FILE` in `.env`), never by name.
  [`.ai/platform/docs/dev-stack.md`](../.ai/platform/docs/dev-stack.md) is the walkthrough.
- `api/` - one Dockerfile for the Go binary. `dev` runs it under air from the bind-mounted
  source; `prod` is the static binary on distroless. `project.env` here is GENERATED by
  `make env` from the project variables in `.env.example` and is gitignored.
- `node/` - one image for frontend, manager and landing.
- `postgres/init/` - runs once on an empty volume: `pg_trgm` and the application role
  `${DB_USER}_app` (`NOSUPERUSER NOBYPASSRLS`,
  [ADR-0009](../.ai/platform/adr/0009-tenancy-by-row-level-security.md)) with default privileges.
- `edge/` - the shared Traefik + mkcert edge, one per Docker host.
- `webhook-echo/` - the receiver the webhook suite delivers to.
- `certs/` - written by `make certs`, gitignored.

- `compose.prod.yml` - production: `api`, `worker` and `scheduler` from ONE static image
  (`${STACK}-api:${RELEASE}`, Dockerfile target `prod`, healthcheck `openenu health`), a Nuxt
  image per app, pinned third-party images, no published ports, `tls.certresolver=letsencrypt`
  on every router. `make prod-check` holds it to that.
- `compose.staging.yml` - the dev stack made safe on a public server: no published port, every
  router behind `${STACK}-allow@file,noindex@file`. Used as `compose.dev.yml:compose.staging.yml`.
  [`.ai/platform/docs/deployment.md`](../.ai/platform/docs/deployment.md) is the walkthrough.

- `compose.ci.yml` - the dev stack with its image builds cached in the GitHub Actions cache;
  set as `COMPOSE_FILE` by `.github/workflows/ci.yml` and nowhere else.
