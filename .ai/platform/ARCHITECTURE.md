# open-enu-go - architecture

What the platform is made of, how it fits together, and where each rule is enforced. The
reasons behind each choice are the ADRs ([`adr/`](adr/README.md)); the how-to for each part
is in [`docs/`](docs/README.md). This document is the map between them.

---

## 1. What it is

A foundation for multi-tenant SaaS products: a Go API, three Nuxt apps, the infrastructure
to run them locally and on a server, and the guardrails that keep a growing codebase in
shape. It works out of the box - `make builddev` brings the whole stack up under trusted
HTTPS - and is meant to be read and extended by people and agents alike:

- **Readable** - paths are *derivable* from a feature name, never discovered by exploration.
- **Extendable without debt** - every rule that matters is also a check that fails.

What a person can do on day one: register and verify by mail, log in, belong to several
workspaces and switch between them, reset a password, create scoped API keys, upload files,
receive notifications in the app and by mail, subscribe a webhook to events, search, and see
every change on the audit trail. An operator administers tenants in a separate console, reads
the audit trail across them, watches the worker queues, switches per-tenant feature flags,
and impersonates a person through the one designed crossing (ADR-0020).

## 2. Stack

| Concern | Choice | Notes |
|---|---|---|
| Language | Go 1.27 (`toolchain go1.27.3`), installed natively | No CGO: the deliverable is a static binary. Native, because `make check` must stay under 60 s |
| HTTP | `net/http` mux + strict server interfaces generated by `oapi-codegen` 2.8 | Spec-first (ADR-0006) |
| Database | PostgreSQL 18 (`pgvector/pgvector:pg18`), `pgx/v5` | No ORM; SQL hand-written in each module's `repository.go` |
| Migrations | `goose/v3`, plain SQL, one directory per module plus the kernel's | `openenu migrate`, as the table owner |
| Tenancy | Row-level security + a transaction-local `app.tenant_id` | ADR-0009 |
| Jobs, outbox | River (Postgres-backed) | Jobs inserted in the writing transaction are the outbox (ADR-0015) |
| Scheduler | `module.Task` on each module, run by `openenu scheduler` | `minute` / `daily` |
| Realtime | Mercure 1.1 hub | OAuth 2.0 access tokens (`at+jwt`), `__Secure-mercure_access_token` cookie |
| Cache | Redis 8.10 through `rueidis`, only inside `kernel/cache` | Tenant-prefixed keys, tag invalidation |
| Rate limits | `httpx.RateLimit`, a token bucket per client address, in memory | On `/api/auth/` and the operator login |
| Auth | HS256 JWTs with the standard library (`kernel/auth`); `sk_...` API keys by hash | Realms by audience (ADR-0019) |
| Passwords | argon2id, `golang.org/x/crypto/argon2`, PHC format | ADR-0022 |
| Encryption | AES-256-GCM, HKDF-SHA256 per-tenant keys, standard library | ADR-0016 |
| Mail | `kernel/mail`: SMTP (Mailpit in dev), a log line without `MAILER_DSN`, a recorder in tests | Plain text, translated |
| Search | `tsvector` + GIN in one `search_index` table | ADR-0017 |
| i18n | `kernel/i18n` catalogues, `en` and `pl` | ADR-0008 |
| Logs | `log/slog` JSON; `kernel/logctx` adds request id, tenant, person, impersonator | [`docs/observability.md`](docs/observability.md) |
| MCP | the official MCP Go SDK | Tools from the spec and the ACL, filtered to the key's scopes |
| Guardrails | `go/analysis` analyzers in `kernel/analysis`, shell checks in `scripts/dev` | §6 |
| Dead code | `deadcode` (blocking for the application), `knip` for TypeScript | `make dead-code` |
| Tests | `testing`, `httptest` against the real router, `testcontainers-go` for Postgres and Redis | [`docs/testing.md`](docs/testing.md) |
| Browser apps | Nuxt 4.6, Vue 3.5, Pinia, Tailwind 4, `@nuxtjs/i18n`, `@nuxt/content` (landing) | Node 26, in the node container only |
| Browser tests | Playwright 1.64 | `make e2e` |
| Edge | Traefik 3.7, one shared instance per Docker host | mkcert CA locally, Let's Encrypt on a server |

**Pinned on purpose** (Dependabot skips exactly these; `make ci` decides when to lift one):

| Dependency | Kept at | Why |
|---|---|---|
| `typescript` | 6.0 | 7 is the native compiler and exports no JavaScript API; vue-tsc, knip and `nuxt prepare` read it |
| `vue-tsc` | 3.3.11 | from 3.3.12 a static attribute holding `//` inside a scoped slot loses the slot's variable (TS2304 in `webhook/pages/settings/webhooks.vue`) |
| `better-sqlite3` | 12 | 13 publishes no prebuilt binary, and `node:26-alpine` has nothing to compile one with |

`esbuild ^0.28` is a root devDependency only so npm hoists the copy vite's peer range
accepts; `@nuxtjs/i18n`'s bundle utilities keep their own 0.25 nested. Go tools are upgraded
with `go get <tool>@latest`, never `go get -u tool`, which upgrades a tool's dependencies
past what it builds with. `make versions-check` keeps Postgres, Redis, Mercure, Go and Node at
one version across every file that names one.

## 4. The shape of a module

Go packages are the unit of visibility, so the shape does the enforcing.

```
backend/internal/module/example/
├── module.yaml        # name, description, depends, enabled - read by `go generate`
├── module.go          # var Module = module.Module{...}: routes, permissions, flags, search,
│                      #   setup, tasks, notifications - the ONLY thing the registry sees
├── MODULE.md          # what it is, what it exposes, what it depends on
├── openapi.json       # its fragment of the contract
├── contract/          # exported: what OTHER modules may import (events, ids, read ports)
├── internal/          # everything else - unimportable from outside this module
│   ├── api.go         #   implements the generated StrictServerInterface (api.gen.go)
│   ├── mount.go       #   wires the module to platform.Services
│   ├── entity.go      #   Project: scoped, versioned, one encrypted column, JSONB attributes
│   ├── command.go     #   the commands, each with its audit action
│   ├── handler.go     #   the only code handed a *scope.Tx - therefore the only writer
│   ├── repository.go  #   the only file with SQL
│   ├── voter.go       #   record-level authorization
│   ├── job.go         #   a background job reporting progress
│   ├── flags.go       #   every flag the module reads, declared
│   ├── setup.go       #   what a new tenant is seeded with
│   ├── fixtures.go    #   deterministic fixtures
│   ├── search.go      #   the searchable declaration: fields + the permission that gates excerpts
│   └── task.go        #   `daily example.sweep`, run by `openenu scheduler`
├── migrations/        # 0001_create_project.sql, ... - each scoped table ends with scope.Policy
├── i18n/              # messages.en.json, messages.pl.json
└── *_test.go          # functional tests through httptest on real Postgres
```

Rules that fall out of the shape:

- Another module may import `example/contract` and nothing else; the compiler refuses
  `example/internal`.
- The kernel is a separate Go module with no dependency on the application, so it cannot
  import it (ADR-0002); `make selftest` proves the build fails if someone tries.
- Only a handler receives a `*scope.Tx`, so a controller holding one is a type error
  (ADR-0013); `writeboundary` covers the rest.
- `scope.Unscoped(ctx, "reason", fn)` is the one way to read across tenants, with a literal
  reason, in a `repository.go` (ADR-0009).

`Example` carries exactly one of every platform concern and is the thing to copy; it is
capped at 1150 lines including tests (`make agents-budget`). Adding a demonstration means
removing one.

## 5. Platform contracts

Each is one Go interface in `kernel/`, one default implementation, the check that forces its
use, and a test against the real backing service. A module receives all of them in one
`*platform.Services` at `Mount` ([`docs/platform-services.md`](docs/platform-services.md)).

| Contract | Kernel package | Enforced by |
|---|---|---|
| Command bus with audit snapshots | `command`, `audit` | Only handlers hold `*scope.Tx`; the bus owns the transaction and writes the trail |
| Tenant scope | `scope` | Row-level security; `scope.Policy` in every scoped table's migration |
| Cache | `cache` | `platformservice`: no Redis client outside the kernel |
| Storage | `storage` | `platformservice`: no `os.Create`/`os.WriteFile` outside the kernel |
| Field encryption | `crypto` | Encrypted columns are never queried; `*_hash` siblings for lookups |
| Optimistic locking | `scope` + `httpx` | `UPDATE ... WHERE version = $n`; zero rows is a 409 with both versions |
| Events, jobs, client broadcast | `event`, `outbox`, `realtime` | River jobs in the writing transaction |
| Full-text search | `search` | `Module.Search` declares fields and a permission; the registry validates it |
| Tenant setup | `setup` | Every module's `Setup` runs for a new workspace |
| GDPR export / erase | `gdpr` | A walker over every registered subject |
| Progress | `progress` | Jobs report through `progress.Reporter`; the UI reads one endpoint |
| Feature flags | `flags` | `flagdeclared`: every key read is declared; the registry checks `Module.Flags` |
| Notifications | `notification` | A type is declared on the module that raises it; rows store keys, not sentences |
| Mail | `mail` | Translated templates; a recorder in tests |

## 6. Guardrails

| Rule | Held by |
|---|---|
| Module boundaries | Go `internal/` - the compiler; `MODULE.md` names every `contract/` export (`docs-check`) |
| Kernel purity | a separate Go module with no dependency edge - the compiler, proved by `selftest` |
| Writes only through the bus | `*scope.Tx` reachability - the compiler - plus `writeboundary` |
| Thin controllers | `thincontroller` |
| SQL only in repositories; `Unscoped` with a reason | `rawsql` |
| A module's tables are its own | `tableowner` |
| Platform services, not local copies | `platformservice` |
| No sentences where a translation key belongs | `rawstring` |
| Text limits in characters, not bytes | `textlen` |
| Every flag read is declared | `flagdeclared` |
| Locale parity | the registry at start-up (API); `make i18n-check` (apps, landing pages) |
| Generated files are fresh; the spec is valid | `gen-check`, `openapi-check` |
| Every operation has a test that reaches it | `make route-coverage` |
| No dead code | `make dead-code` - `knip` and `deadcode` block; the kernel's unused exports are advisory |
| Links, indexes, platform/project split | `make docs-check` |
| No long dash | `make typography-check` |
| One version per service | `make versions-check` |
| Instruction and module budgets | `make agents-budget` |
| Shell portability; the production stack's shape | `make shell-check`, `make prod-check` |

Every analyzer ships with a fixture under `testdata/` that breaks it, and `make selftest`
breaks a throwaway copy of the tree to watch each guardrail fail. A guardrail that has not
been seen to fail is not a guardrail ([`docs/guardrails.md`](docs/guardrails.md)).

## 7. The browser apps

`frontend` (tenant users) and `manager` (operators) are single-page apps - there is no
session to render on the server - and `landing` renders on the server from `@nuxt/content`
markdown in both locales. All three extend `@open-enu/ui-kit`, which holds the one `useApi`
every request goes through (the in-memory token, one shared refresh on 401, cookie
credentials, the typed 409), the auth store, tenant-scoped realtime over Mercure, the
conflict bar, uploads with real progress, and the UI primitives. Each module is a Nuxt layer
discovered from its directory (ADR-0007), contributing pages, navigation, settings tabs,
injection points and translations with no central file edited. The operator console is a
separate bundle on a separate host, talking only to `/api/manager`
([`docs/frontend-conventions.md`](docs/frontend-conventions.md),
[`docs/landing.md`](docs/landing.md)).

## 8. Dev stack

`make builddev` brings everything up from nothing: Postgres, Redis, Mercure, Mailpit, the
`api`, `worker` and `scheduler` (one image, run under `air`, so Go edits are live), the three
Nuxt dev servers and a webhook echo receiver, behind the shared Traefik edge on 80/443 with
a locally trusted CA. `make smoke` checks every host for content, not just a status code.
The application connects as a non-owner role under RLS; migrations run as the owner. Details
and troubleshooting: [`docs/dev-stack.md`](docs/dev-stack.md).

## 9. Deployment

Two stages, on one server or two, sharing only the edge. Staging is the dev stack on a
server behind an IP allowlist, where changes are made and looked at; production is immutable
images - one static binary for `api`, `worker` and `scheduler`, one Nuxt image per app.
`make buildstaging` / `make buildprod` take a bare VPS to a running product after a
read-only preflight; `make promote` moves production to exactly the commit staging ran.
Production refuses to call itself finished without an off-box, encrypted, restore-tested
backup (ADR-0024 to ADR-0026, [`docs/deployment.md`](docs/deployment.md)).

## 10. What this is not

- Not a no-code platform: schema changes are migrations (ADR-0012).
- Not multi-level tenancy: tenants only, with the door open (ADR-0011).
- Not undo-capable, though the data for it is recorded (ADR-0014).
- Not zero-downtime on deploy; two replicas behind health-gated rotation is the path when
  needed.
- Not a framework to depend on unchanged: projects are renamed copies that pull platform
  updates with `make platform-update` (ADR-0002).
